# Terraform – Sensitive Parameters

## What is a Sensitive Parameter?

A **sensitive parameter** is a value that should not be displayed openly in Terraform output.

Typical examples include:

* Passwords
* API keys
* Tokens
* Database credentials
* Private keys
* Secrets

Terraform provides the `sensitive` argument to prevent sensitive values from being displayed in normal CLI output.

> **Important:** `sensitive = true` hides the value from Terraform CLI output, but it does **not** mean the value is completely removed from Terraform state.

---

# 1. Base Code – Password Exposed

```hcl
resource "local_file" "foo" {
  content  = "supersecretpassw0rd"
  filename = "password.txt"
}
```

Terraform plan can show the password directly:

```text
+ resource "local_file" "foo" {
    + content = "supersecretpassw0rd"
    + filename = "password.txt"
}
```

### Problem

The password is visible in the Terraform output.

This is **not recommended** for real credentials.

---

# 2. Using a Variable

Instead of hardcoding the password directly in the resource:

```hcl
variable "password" {
  default = "supersecretpassw0rd"
}

resource "local_file" "foo" {
  content  = var.password
  filename = "password.txt"
}
```

The password is now stored in a variable, but it is **still not sensitive**.

Terraform can still display the value.

---

# 3. Marking the Variable as Sensitive

Use:

```hcl
variable "password" {
  default   = "supersecretpassw0rd"
  sensitive = true
}

resource "local_file" "foo" {
  content  = var.password
  filename = "password.txt"
}
```

Now Terraform knows that the variable contains sensitive information.

The important setting is:

```hcl
sensitive = true
```

Terraform will hide the value in CLI output.

Instead of:

```text
content = "supersecretpassw0rd"
```

you may see:

```text
content = (sensitive value)
```

---

# 4. `local_sensitive_file`

The Local provider also provides a specific resource type for sensitive files:

```hcl
resource "local_sensitive_file" "foo" {
  content  = "supersecretpassw0rd"
  filename = "password.txt"
}
```

Terraform will treat the file content as sensitive.

The output can show:

```text
~ content = (sensitive value)
```

rather than exposing the actual password.

---

# 5. Sensitive Values in Outputs

Suppose we have:

```hcl
resource "local_sensitive_file" "foo" {
  content  = "supersecretpassw0rd"
  filename = "password.txt"
}

output "pass" {
  value = local_sensitive_file.foo.content
}
```

Terraform will complain because the output is exposing a sensitive value.

You must explicitly mark the output as sensitive:

```hcl
output "pass" {
  value     = local_sensitive_file.foo.content
  sensitive = true
}
```

Now Terraform understands that the output contains sensitive information.

---

# 6. AWS RDS Password

A common real-world example is an AWS RDS database.

```hcl
resource "aws_db_instance" "default" {
  allocated_storage    = 10
  db_name              = "mydb"
  engine               = "mysql"
  engine_version       = "8.0"
  instance_class       = "db.t3.micro"
  username             = "foo"
  password             = "foobarbaz"
  parameter_group_name = "default.mysql8.0"
  skip_final_snapshot  = true
}
```

The problem is that the database password is directly hardcoded:

```hcl
password = "foobarbaz"
```

This is a bad practice for production.

---

# 7. Better Approach – Sensitive Variable

Create a sensitive variable:

```hcl
variable "db_password" {
  description = "RDS database password"
  type        = string
  sensitive   = true
}
```

Then use it in RDS:

```hcl
resource "aws_db_instance" "default" {
  allocated_storage    = 10
  db_name              = "mydb"
  engine               = "mysql"
  engine_version       = "8.0"
  instance_class       = "db.t3.micro"

  username = "foo"
  password = var.db_password

  parameter_group_name = "default.mysql8.0"
  skip_final_snapshot  = true
}
```

The password can then be supplied through a variable file, environment variable, or preferably a dedicated secrets-management solution.

---

# 8. Important Security Point

`sensitive = true` **does not encrypt or remove the secret from Terraform state**.

For example:

```hcl
variable "password" {
  sensitive = true
}
```

means:

```text
Terraform CLI output
        ↓
Password hidden
        ↓
(sensitive value)
```

But the value may still exist in:

```text
Terraform State
        ↓
terraform.tfstate
```

Therefore, Terraform state must also be protected.

For production environments, use:

* Secure remote state
* Encryption at rest
* Restricted access to state
* State locking where supported
* Secrets Manager / Vault / equivalent secret-management solutions

---

# 9. Sensitive vs `local_sensitive_file`

| Method                         | Purpose                                                    |
| ------------------------------ | ---------------------------------------------------------- |
| `sensitive = true` on variable | Marks a variable value as sensitive                        |
| `sensitive = true` on output   | Prevents sensitive output from being displayed             |
| `local_sensitive_file`         | Creates a local file whose content is treated as sensitive |
| Secrets Manager / Vault        | Dedicated solution for storing and managing secrets        |

---

# 10. Interview Questions

### Q1. What does `sensitive = true` do?

**Answer:**

It tells Terraform that a value is sensitive and prevents Terraform from displaying that value in normal CLI output such as `plan` and `apply`.

---

### Q2. Does `sensitive = true` encrypt the password?

**Answer:**

**No.**

It primarily prevents the value from being displayed in Terraform CLI output. The value can still be stored in Terraform state.

---

### Q3. Can I use a sensitive variable as an RDS password?

**Answer:**

Yes.

```hcl
variable "db_password" {
  type      = string
  sensitive = true
}

resource "aws_db_instance" "default" {
  password = var.db_password
}
```

---

### Q4. What happens if I output a sensitive value?

Terraform requires the output to be explicitly marked as sensitive:

```hcl
output "password" {
  value     = var.db_password
  sensitive = true
}
```

---

### Q5. What is `local_sensitive_file`?

**Answer:**

`local_sensitive_file` is a Local provider resource used to create a local file while treating its content as sensitive in Terraform's output.

Example:

```hcl
resource "local_sensitive_file" "password" {
  content  = var.password
  filename = "password.txt"
}
```

---

# Key Interview Takeaway

> **`sensitive = true` hides sensitive values from Terraform CLI output, but it does not make the value secret or remove it from Terraform state. Protect your state and use a proper secrets-management solution for production credentials.**
