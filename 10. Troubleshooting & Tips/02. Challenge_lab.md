# Terraform Challenge 1 — Legacy Provider Walkthrough & Provider Upgrade

## Challenge

> A developer at a small corp created a Terraform file for provisioning certain resources. The code was written a few years ago with an old Terraform version.
>
> a. Create infrastructure using the provided code **without modifications**
> b. Verify if the code works with the **latest** version of Terraform and provider
> c. Modify & fix the code so that it works with the latest version of Terraform
> d. Feel free to edit the code

## Starting code (as provided)

```hcl
provider "aws" {
  version = "~> 2.54"
  region  = "eu-west-1"
  access_key = "AKIAIOSFODNN7EXAMPLE"
  secret_key = "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY"
}

provider "digitalocean" {}

terraform {
    required_version = "0.12.31"
}


resource "aws_eip" "SRIlabs_app_ip" {
  vpc      = true
}
```

> Note: the `access_key`/`secret_key` values above are AWS's well-known public example/placeholder credentials from AWS documentation, not real secrets. Hardcoding real credentials directly in a `.tf` file like this is bad practice regardless — that's part of why it gets cleaned up below.

To satisfy requirement **(a)** — running the code *without modification* — we need to actually install Terraform 0.12.31 and run it with that.

### Step 7: Destroy

```

```

### Step 8: Get the latest Terraform version

Download and check the current release — at the time of writing: **1.16.0**.

### Step 9: Fix the code for the latest Terraform (requirement c/d)

a. Remove `required_version` — it pinned the config to 0.12.31 and is why init failed on the newer binary
b. Update the DigitalOcean provider block to use `required_providers` with an explicit `source` (get the current template from the Terraform Registry) — the old implicit `terraform-providers/digitalocean` source is deprecated
c. Remove the AWS provider's hardcoded `access_key`/`secret_key`/`version` — use `aws configure` / environment variables instead, and drop the old `version` argument (version pinning now belongs in `required_providers`, not inside the `provider` block)
d. Delete `.terraform.lock.hcl` (referred to above as `.terraform.local.hcl`) since it still locks in the old provider versions
e. Change `vpc = true` → `domain = "vpc"` on the `aws_eip` resource, since `vpc` is deprecated in newer AWS provider versions
f. Run `terraform init` again

### Fixed code (final)

```hcl
provider "aws" {
  region = "eu-west-1"
}

terraform {
  required_providers {
    digitalocean = {
      source = "digitalocean/digitalocean"
    }
  }
}

resource "aws_eip" "SRIlabs_app_ip" {
  domain = "vpc"
}
```

## Summary

| | Original (0.12.31) | Fixed (1.16.0) |
|---|---|---|
| `required_version` | `"0.12.31"` (blocks new Terraform) | removed |
| DigitalOcean provider | empty block, implicit legacy source | `required_providers` block with explicit `source = "digitalocean/digitalocean"` |
| AWS provider | `version = "~> 2.54"`, hardcoded `access_key`/`secret_key` | just `region`; credentials via `aws configure`/env vars |
| `aws_eip` argument | `vpc = true` (deprecated) | `domain = "vpc"` |
| Lock file | `.terraform.lock.hcl` pinned to old providers | deleted, regenerated on `init` |

**Core lesson:** Terraform config written against 0.12.x needs three things updated to run cleanly on a modern release: the `required_version` constraint, the provider *source address* (post-0.13 provider namespacing), and any deprecated resource arguments (like `vpc` on `aws_eip`, replaced by `domain`).
