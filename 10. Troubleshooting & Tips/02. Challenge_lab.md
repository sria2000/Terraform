# KPLabs Terraform Challenge 1 – Terraform 0.12 to Modern Terraform

## Objective

Complete Challenge 1 using the legacy Terraform version first, create an AWS Elastic IP, destroy it, and then clean up the configuration for modern Terraform.

> **Note:** The challenge notes mention Terraform `1.16.0` as the latest version at the time they were written. Terraform releases change over time, so use the version required by your course/challenge environment.

## 1. Download Terraform 0.12.31

Download:

- https://releases.hashicorp.com/terraform/0.12.31/
- File: `terraform_0.12.31_windows_amd64.zip`

Extract the ZIP and copy `terraform.exe` to:

```text
D:\Terraform\challenge\kplabs-terraform-challenges\challenge-1
```

## 2. Verify Terraform 0.12.31

From the challenge directory:

```cmd
terraform.exe version
```

Expected:

```text
Terraform v0.12.31
```

## 3. Initialise the Legacy Configuration

Run:

```cmd
terraform.exe init
```

The legacy configuration may install providers such as:

```text
digitalocean 2.95.0
aws 2.70.4
```

You may see a warning that the DigitalOcean provider has moved to:

```text
digitalocean/digitalocean
```

This is expected when using the old Terraform/provider configuration.

## 4. Configure AWS Credentials

Do not put AWS credentials directly into the Terraform configuration.

Run:

```cmd
aws configure
```

Enter the required values:

```text
AWS Access Key ID:
AWS Secret Access Key:
Default region name: eu-west-1
Default output format: None
```

If temporary credentials are required, configure them using your approved AWS credential mechanism.

> **Security:** Never commit AWS access keys, secret keys, or session tokens to Git or Terraform `.tf` files.

## 5. Run Terraform Plan

Run:

```cmd
terraform plan
```

The expected plan creates:

```text
aws_eip.kplabs_app_ip
```

Expected summary:

```text
Plan: 1 to add, 0 to change, 0 to destroy.
```

## 6. Apply the Configuration

Run:

```cmd
terraform apply -auto-approve
```

Check the AWS Console:

```text
AWS Console
→ EC2
→ Elastic IPs
```

You should see the Elastic IP.

### Requirement 1 Complete

At this point the first requirement of the challenge is complete.

## 7. Destroy the Resource

Use:

```cmd
terraform destroy -auto-approve
```

> **Correction:** The correct option is `-auto-approve`, not `-auto-destroy`.

Verify in the AWS Console that the Elastic IP has been removed.

# Modern Terraform Upgrade

## 8. Use a Modern Terraform Version

Install/use the Terraform version required by the challenge.

Check it with:

```cmd
terraform version
```

## 9. Clean the Old Configuration

The old challenge configuration was written for Terraform 0.12. Update the legacy syntax before using a modern Terraform version.

### Remove an old `required_version` if the challenge specifically asks you to

For example, remove:

```hcl
required_version = "0.12.31"
```

Otherwise a modern Terraform binary may be rejected by the configuration.

### Update the DigitalOcean provider source

Old Terraform/provider configurations can use legacy provider addressing. Modern Terraform uses:

```hcl
digitalocean = {
  source = "digitalocean/digitalocean"
}
```

### Update the AWS provider source

Modern Terraform uses:

```hcl
aws = {
  source = "hashicorp/aws"
}
```

### Remove hard-coded AWS credentials

The AWS provider should use the AWS CLI credential configuration or another secure credential mechanism.

### Remove old local metadata if required by the challenge

If the challenge directory contains the old `.terraform.local.hcl` mentioned in the notes and it belongs to the old setup, remove it as instructed.

Do not confuse this with:

```text
.terraform/
.terraform.lock.hcl
```

`.terraform/` is the working directory created by Terraform, while `.terraform.lock.hcl` records provider dependency selections and checksums.

## 10. Change the AWS Elastic IP Syntax

Old configuration:

```hcl
resource "aws_eip" "kplabs_app_ip" {
  vpc = true
}
```

Modern configuration:

```hcl
resource "aws_eip" "kplabs_app_ip" {
  domain = "vpc"
}
```

This is one of the key changes in Challenge 1.

## 11. Correct Modern Configuration

If only AWS is required for this challenge, a clean modern configuration is:

```hcl
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"
    }
  }
}

provider "aws" {
  region = "eu-west-1"
}

resource "aws_eip" "kplabs_app_ip" {
  domain = "vpc"
}
```

If the challenge specifically requires DigitalOcean to remain declared:

```hcl
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"
    }

    digitalocean = {
      source = "digitalocean/digitalocean"
    }
  }
}

provider "aws" {
  region = "eu-west-1"
}

resource "aws_eip" "kplabs_app_ip" {
  domain = "vpc"
}
```

If DigitalOcean is not used anywhere in the configuration, it is cleaner not to retain an unnecessary provider requirement.

## 12. Re-run Terraform Init

After changing provider configuration:

```cmd
terraform init
```

Terraform will initialise the modern provider configuration.

## 13. Run Terraform Plan

Run:

```cmd
terraform plan
```

The plan should show:

```text
# aws_eip.kplabs_app_ip will be created
```

Expected summary:

```text
Plan: 1 to add, 0 to change, 0 to destroy.
```

## 14. Apply If Required

If the challenge requires the resource to be created again:

```cmd
terraform apply -auto-approve
```

Check:

```text
AWS Console
→ EC2
→ Elastic IPs
```

## 15. Final Destroy

When the challenge is complete:

```cmd
terraform destroy -auto-approve
```

# Important Terraform Revision Points

## Provider Source

Modern AWS provider declaration:

```hcl
aws = {
  source = "hashicorp/aws"
}
```

Modern DigitalOcean provider declaration:

```hcl
digitalocean = {
  source = "digitalocean/digitalocean"
}
```

## Resource Reference Syntax

A resource reference normally has the form:

```text
resource_type.resource_name.attribute
```

Example:

```hcl
aws_vpc.main.id
```

Therefore:

```hcl
domain = vpc
```

means Terraform interprets `vpc` as an expression/reference, not as the literal text `vpc`.

Use:

```hcl
domain = "vpc"
```

## Commands

| Command | Purpose |
|---|---|
| `terraform init` | Initialise the working directory and install dependencies |
| `terraform plan` | Preview proposed changes |
| `terraform apply` | Apply changes |
| `terraform destroy` | Destroy managed infrastructure |
| `terraform fmt` | Format Terraform configuration |
| `terraform validate` | Validate configuration |
