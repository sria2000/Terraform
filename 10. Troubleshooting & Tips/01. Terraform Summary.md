# Terraform Exam Revision Guide

> **Purpose:** Quick revision guide for the Terraform exam.  
> **Source:** User-provided Terraform notes, cleaned up, reordered, corrected, and supplemented with additional exam-focused questions.

## 1. Terraform Providers

### Q1. Is a `provider` block mandatory in every Terraform configuration?
**Answer: No.**

A provider configuration block is not always required. If Terraform can use the provider's default configuration and no provider-specific settings are needed, the explicit `provider` block may be omitted.

A provider block is needed when configuring provider-specific settings such as region, credentials, endpoints, aliases, etc.

### Q2. What is a provider?
**Answer:** A provider is a plugin that lets Terraform interact with an external API/platform such as AWS, Azure, Google Cloud, Kubernetes, or local resources.

### Q3. Where are provider plugins installed locally?
After `terraform init`, providers are normally installed under the `.terraform/providers` directory for the working directory (unless a configured plugin cache/mirror changes the installation mechanism).

Example:
```text
.terraform/providers/registry.terraform.io/hashicorp/local/2.9.0/windows_amd64/
```

### Q4. What is a provider alias?
**Answer:** An alias allows multiple configurations of the same provider to coexist.

Typical use case: managing resources in different AWS regions/accounts.

```hcl
provider "aws" {
  region = "eu-west-2"
}

provider "aws" {
  alias  = "us_east"
  region = "us-east-1"
}

resource "aws_instance" "example" {
  provider = aws.us_east
  # ...
}
```

### Q5. Where should credentials be stored?
**Answer:** Prefer provider-supported environment variables, credential files, workload identity/roles, or other secure mechanisms rather than hard-coding credentials in `.tf` files.

**Exam point:** Do not put long-lived secrets directly into Terraform configuration or source control.

## 2. Terraform Settings and Required Providers

### Q6. What is the `terraform` block used for?
**Answer:** It configures Terraform itself and its dependencies.

Common settings include:
- Required Terraform version
- Required providers and provider version constraints
- Backend configuration
- Other Terraform-level settings supported by the current Terraform version

Example:
```hcl
terraform {
  required_version = ">= 1.6.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.54"
    }
  }
}
```

### Q7. Can region and credentials be configured in `required_providers`?
**Answer: No.**

`required_providers` declares provider dependency information such as source and version constraints. Provider configuration such as AWS region belongs in a `provider` block.

### Q8. What are version constraints?
**Answer:** Version constraints define which provider/Terraform versions are acceptable.

Common operators:
- `>=`
- `<=`
- `>`
- `<`
- `=`
- `~>`
- combinations such as `>= 5.0, < 6.0`

**Important:** `~>` is the pessimistic constraint operator and is commonly tested.

**Answer:**
1. **Official** — published and maintained by HashiCorp.
2. **Partner** — published/maintained by a verified HashiCorp partner.
3. **Community** — published/maintained by the community.

**Answer: Yes.**

Custom providers can be developed and distributed; they are not automatically "Official" providers simply because the user created them.

## 4. Core Terraform Commands

### Q11. What does `terraform init` do?
**Answer:** Initializes a Terraform working directory.

It can:
- Install required providers
- Install/download child modules
- Initialize or configure the backend
- Prepare the working directory for subsequent Terraform commands

It is normally the first command run after creating or cloning a Terraform configuration.

### Q12. Is `terraform init` safe to run multiple times, including in production?
**Answer: Yes.**

`terraform init` is designed to be repeatable/idempotent. It does not itself apply infrastructure changes.

### Q13. What does `terraform init -upgrade` do?
**Answer:** Re-evaluates dependency selections and upgrades providers/modules where permitted by the configured constraints, subject to the dependency lock file and other configuration.

**Exam trap:** `init -upgrade` does not mean "ignore all version constraints and install anything."

### Q14. What does `terraform plan` do?
**Answer:** Creates an execution plan showing what Terraform intends to change.

Normally:
- It does **not** modify real infrastructure.
- It does **not** normally modify the state file merely because it detects drift.

### Q15. What does `terraform plan -out=FILE` do?
**Answer:** Saves the generated execution plan to a file.

This is useful when you want to review a plan and then apply that exact saved plan.

```bash
terraform plan -out=tfplan
terraform apply tfplan
```

### Q16. What does `terraform apply` do?
**Answer:** Applies the proposed changes to reach the desired configuration.

Terraform updates state as the operation progresses.

### Q17. What is the default local state file called?
**Answer:** `terraform.tfstate`

### Q18. Is `terraform destroy` the only way infrastructure can be destroyed?
**Answer: No.**

For example, if a managed resource is removed from the configuration and an apply is performed, Terraform may plan to destroy that resource because it is no longer desired.

`terraform destroy` is a convenient command to destroy all resources managed by the configuration.

## 5. Formatting and Validation

### Q19. What does `terraform fmt` do?
**Answer:** Rewrites Terraform configuration files into Terraform's canonical formatting style.

It modifies files.

### Q20. Does `terraform fmt` ask for confirmation?
**Answer: No.**

### Q21. What does `terraform fmt -check` do?
**Answer:** Checks whether files are correctly formatted without modifying them. It returns a non-zero exit status when formatting changes are needed.

### Q22. What does `terraform fmt -recursive` do?
**Answer:** Formats Terraform files in the current directory and recursively in subdirectories.

### Q23. What does `terraform validate` do?
**Answer:** Validates the syntax and internal consistency of a Terraform configuration.

It requires an initialized working directory when referenced providers/modules need to be available.

### Q24. If you have not run `terraform init`, can `terraform validate` always run successfully?
**Answer: No.**

For a configuration requiring initialization to make referenced providers/modules available, run `terraform init` first.

### Q25. Does `terraform plan` also perform validation?
**Answer: Yes.**

`terraform plan` performs configuration validation as part of planning.

## 6. Refresh and Drift

### Q26. What does refreshing state mean?
**Answer:** Reading the current information from managed remote objects and reconciling Terraform's state information with what exists remotely.

### Q27. Is `terraform refresh` recommended?
**Answer:** The standalone `terraform refresh` command is deprecated.

Modern Terraform workflows generally refresh state as part of planning/applying rather than using the old standalone command.

### Q28. Does refresh modify real infrastructure?
**Answer:** No. Refresh reads remote infrastructure; it updates Terraform's state representation rather than changing the remote object.

## 7. Resources

### Q29. What is a resource block?
**Answer:** A resource block declares an infrastructure object that Terraform manages.

```hcl
resource "aws_instance" "web" {
  ami           = "ami-123"
  instance_type = "t2.micro"
}
```

### Q30. In the example above, what are the resource type, local name, argument name, and argument value?
**Answer:**
- `aws_instance` = resource type
- `web` = local name/reference name
- `ami` = argument name
- `"ami-123"` = argument value

### Q31. Can the same resource type be used more than once?
**Answer: Yes.**

```hcl
resource "aws_instance" "web" {}
resource "aws_instance" "app" {}
```

### Q32. Can two resource blocks have the same resource type and local name in the same module?
**Answer: No.**

The combination of resource type and local name must be unique within a module.

## 8. Terraform Data Types

### Q33. What are Terraform's main primitive and collection types?
**Answer:**
- `string`
- `number`
- `bool`
- `list`
- `set`
- `map`
- `object`
- `tuple`

Terraform also has the special value `null`.

### Q34. What is a string?
A sequence of Unicode characters.

```hcl
"hello"
```

### Q35. What is a number?
A numeric value.

```hcl
42
```

### Q36. What is a bool?
A Boolean value:

```hcl
true
false
```

### Q37. What is a list?
An ordered sequence of values. Duplicate values are allowed.

```hcl
["a", "b", "a"]
```

### Q38. What is a set?
An unordered collection of unique values.

```hcl
toset(["a", "b", "a"])
# => a set containing "a" and "b"
```

### Q39. What is a map?
A collection of key/value pairs.

```hcl
{
  environment = "prod"
  team        = "platform"
}
```

### Q40. Does Terraform support an `array` type?
**Answer: No.**

Terraform uses **list**, **set**, and **tuple** rather than an `array` type.

## 9. State Management

### Q41. What is Terraform state?
**Answer:** Terraform state records the information Terraform uses to map configuration to real-world resources and track managed infrastructure.

### Q42. What command is used for advanced state management?
**Answer:** `terraform state`

Important subcommands include:
- `terraform state list`
- `terraform state show`
- `terraform state mv`
- `terraform state rm`
- `terraform state pull`
- `terraform state push`

### Q43. What does `terraform state list` do?
Lists resources tracked in state.

### Q44. What does `terraform state show` do?
Shows detailed state attributes for a resource instance.

### Q45. What does `terraform state mv` do?
Moves a resource instance from one state address to another.

Useful during refactoring without recreating the underlying infrastructure.

### Q46. What does `terraform state rm` do?
Removes an object from Terraform state **without destroying the real remote object**.

### Q47. What does `terraform state pull` do?
Retrieves the current state from the configured backend and writes it to standard output.

### Q48. What does `terraform state push` do?
Uploads a local state file to a configured backend.

**Exam warning:** It is an advanced and potentially dangerous operation.

## 10. Terraform Debugging

### Q49. How do you enable Terraform logging?
Set the `TF_LOG` environment variable.

Common levels:
- `TRACE`
- `DEBUG`
- `INFO`
- `WARN`
- `ERROR`

Example:
```bash
TF_LOG=DEBUG terraform plan
```

### Q50. How can Terraform logs be written to a file?
Use `TF_LOG_PATH`.

```bash
TF_LOG=DEBUG
TF_LOG_PATH=terraform.log
```

## 11. Importing Existing Infrastructure

### Q51. What is Terraform import used for?
**Answer:** It associates existing infrastructure with Terraform-managed resources by importing it into state.

### Q52. Can Terraform import blocks be used?
**Answer: Yes.**

Example:
```hcl
import {
  to = aws_security_group.mysg
  id = "sg-07f13feb262ba8b6f"
}
```

### Q53. Can Terraform generate configuration for imported resources?
**Answer:** Modern Terraform supports configuration generation during import workflows using:

```bash
terraform plan -generate-config-out=generated.tf
```

The generated configuration should be reviewed and adapted before relying on it.

### Q54. Does importing an existing resource automatically mean Terraform will manage every aspect of it correctly?
**Answer: No.**

The resource must have suitable configuration, and you should run `terraform plan` to reconcile configuration, state, and the real object.

## 12. Local Values

### Q55. What are local values?
**Answer:** Local values give names to expressions so they can be reused without repeating the same expression.

```hcl
locals {
  common_tags = {
    Team = "payments-team"
  }
}
```

Reference them with:

```hcl
local.common_tags
```

### Q56. Are locals referenced using `locals` or `local`?
**Answer:** The block is `locals` (plural), but references use `local` (singular).

### Q57. Can a local value reference variables and other locals?
**Answer: Yes.**

## 13. Workspaces

### Q58. What are Terraform CLI workspaces?
**Answer:** Workspaces allow multiple state instances to be associated with the same Terraform configuration.

### Q59. What commands create and select a workspace?
```bash
terraform workspace new dev
terraform workspace select prod
```

### Q60. Where can local workspace state be stored?
For non-default local workspaces, Terraform commonly uses a `terraform.tfstate.d` directory.

### Q61. Are workspaces suitable for strong isolation between environments such as production and development?
**Answer:** Generally, no.

For strong isolation, separate configurations, accounts/subscriptions/projects, credentials, and/or separate state/backends are often more appropriate.

## 14. Modules

### Q62. What is a Terraform module?
**Answer:** A module is a collection of Terraform configuration files used together as a reusable unit.

### Q63. What is the root module?
**Answer:** The module containing the Terraform configuration from the current working directory. It is the entry point for that Terraform configuration.

### Q64. What is a child module?
**Answer:** A module called by another module.

### Q65. Where can a module source come from?
Examples include:
- Local paths
- Terraform Registry
- Git repositories
- HTTP URLs
- Other supported module source types

### Q66. How do you call a module?
Use a `module` block with a `source`.

```hcl
module "ec2" {
  source = "../../modules/ec2"
}
```

### Q67. When does Terraform download/install module source code?
**Answer:** During `terraform init`.

### Q68. What is the rule for local module paths?
A local module source path starts with `./` or `../`.

Example:
```hcl
module "ec2" {
  source = "../../modules/ec2"
}
```

Local module sources do not support module version constraints.

### Q69. How do you reference a generic Git repository as a module?
Use the `git::` prefix.

```hcl
module "vpc" {
  source = "git::https://example.com/vpc.git"
}
```

## 15. Module Outputs

### Q70. What is a module output?
**Answer:** An output exposes a value from a child module to its caller.

Child module:
```hcl
output "instance_id" {
  value = aws_instance.myec2.id
}
```

Root module:
```hcl
module.ec2.instance_id
```

### Q71. What is the general syntax for a child module output reference?
```text
module.<MODULE_NAME>.<OUTPUT_NAME>
```

## 16. Module Versioning and Registry

### Q72. Is a module `version` argument mandatory?
**Answer: No.**

For registry modules, explicitly constraining versions is recommended to avoid unexpected changes.

```hcl
module "ec2-instance" {
  source  = "terraform-aws-modules/ec2-instance/aws"
  version = "5.6.1"
}
```

### Q73. What is the Terraform Registry?
**Answer:** A registry hosting reusable Terraform modules and providers.

A public module source commonly follows:

```text
<namespace>/<name>/<provider>
```

with the registry hostname implied when omitted.

### Q74. What are important requirements for publishing a module to the public Terraform Registry?
Typical requirements include:
- Public GitHub repository
- Correct repository/module naming convention
- Standard module structure
- Release tags using semantic versioning such as `v1.0.0`

**Exam trap:** These are public registry requirements; private module registries have different requirements.

## 17. Terraform Functions

### Q75. Does Terraform support built-in functions?
**Answer: Yes.**

Terraform provides many built-in functions for transforming and combining values.

### Q76. Does Terraform support user-defined functions?
**Answer: No.**

Terraform has built-in functions but does not provide a mechanism for defining arbitrary custom functions in HCL.

### Q77. What are examples of numeric functions?
- `abs`
- `ceil`
- `floor`
- `max`
- `min`

### Q78. What are examples of string functions?
- `concat`
- `replace`
- `split`
- `join`
- `lower`
- `upper`

### Q79. What are examples of collection functions?
- `element`
- `keys`
- `length`
- `merge`
- `sort`
- `slice`

### Q80. What does `lookup()` do?
Retrieves a value from a map by key, returning a supplied default if the key is absent.

```hcl
lookup({a = "ay", b = "bee"}, "c", "what?")
# "what?"
```

### Q81. What does `zipmap()` do?
Creates a map from a list of keys and a corresponding list of values.

### Q82. What does `index()` do?
Returns the index of a value in a list.

```hcl
index(["a", "b", "c"], "b")
# 1
```

### Q83. What does `element()` do?
Retrieves an element from a list or tuple by index.

```hcl
element(["a", "b", "c"], 1)
# "b"
```

### Q84. What does `toset()` do?
Converts a collection such as a list to a set.

Duplicates are removed because sets contain unique values.

### Q85. What does `timestamp()` return?
The current UTC timestamp as an RFC 3339 formatted string.

### Q86. What does `file()` do?
Reads the contents of a file and returns them as a string.

```hcl
policy = file("${path.module}/ec2-policy.json")
```

**Important:** `file()` reads files that are already present on disk; it is not a general-purpose remote file downloader.

## 18. Meta-Arguments

### Q87. What are Terraform meta-arguments?
**Answer:** Special arguments that change how Terraform manages resources/modules rather than representing provider-specific resource attributes.

Common resource meta-arguments include:
- `count`
- `for_each`
- `depends_on`
- `provider`
- `lifecycle`

### Q88. What does `depends_on` do?
Creates an explicit dependency when Terraform cannot infer the dependency from resource references.

### Q89. What does `count` do?
Creates multiple instances based on a whole-number count.

```hcl
resource "aws_instance" "web" {
  count = 3
  # ...
}
```

Instances are addressed with indices such as:
```text
aws_instance.web[0]
aws_instance.web[1]
aws_instance.web[2]
```

### Q90. What does `for_each` do?
Creates one instance for each element of a map or set of strings.

Example:
```hcl
resource "aws_instance" "web" {
  for_each = toset(["dev", "prod"])
  # ...
}
```

### Q91. What is a key difference between `count` and `for_each`?
**Answer:** `count` uses numeric indexes; `for_each` uses keys/set elements.

`for_each` is often preferable when each instance has a meaningful stable key.

### Q92. What does the `provider` meta-argument do?
Selects a particular provider configuration, commonly an aliased provider.

### Q93. What does `lifecycle` do?
Customizes resource lifecycle behavior.

Example:
```hcl
lifecycle {
  ignore_changes = [tags]
}
```

Other important lifecycle arguments include:
- `create_before_destroy`
- `prevent_destroy`
- `ignore_changes`
- `replace_triggered_by`

### Q94. What does `ignore_changes` do?
Tells Terraform to ignore changes to specified attributes when deciding whether to update the resource.

**Exam warning:** It does not mean Terraform forgets the resource.

## 19. `count.index`

### Q95. What is `count.index`?
The zero-based index of the current resource instance when `count` is used.

```hcl
resource "aws_instance" "web" {
  count = 3
  # count.index = 0, 1, or 2
}
```

## 22. Input Variables

### Q100. What are input variables?
**Answer:** Input variables parameterize Terraform configurations by allowing values to be supplied from outside the configuration.

```hcl
variable "instance_type" {
  type    = string
  default = "t2.micro"
}
```

Use:
```hcl
var.instance_type
```

### Q101. What is a `.tfvars` file?
A variable definition file used to assign values to input variables.

Example:
```hcl
instance_type = "m5.large"
app_port      = 8080
```

### Q102. How can you explicitly select a `.tfvars` file?
```bash
terraform plan -var-file="prod.tfvars"
```

### Q103. What are common ways to provide variable values?
- Default values in variable declarations
- `terraform.tfvars`
- `terraform.tfvars.json`
- Automatically loaded `*.auto.tfvars` / `*.auto.tfvars.json`
- `-var` / `-var-file`
- Environment variables named `TF_VAR_<variable_name>`

### Q104. What environment variable convention does Terraform use for input variables?
```text
TF_VAR_<variable_name>
```

Example:
```text
TF_VAR_instance_type=m5.large
```

### Q105. What happens if a required variable has no value?
**Answer:** Terraform can prompt interactively for the value when the command supports interactive input. In non-interactive automation, the command will fail if the required value is not supplied.

## 23. Variable Precedence

### Q106. Which variable source has higher precedence?
A simplified exam-focused ordering is:

1. Environment variables
2. `terraform.tfvars`
3. `terraform.tfvars.json`
4. `*.auto.tfvars` / `*.auto.tfvars.json` in lexical order
5. Explicit `-var` and `-var-file` command-line options

**Rule:** Later sources override earlier sources.

### Q107. Which normally wins if a variable is defined in both `terraform.tfvars` and with `-var`?
**Answer:** The explicit command-line `-var` value wins.

## 24. Variable Validation, Types, Sensitive Values

### Q108. Can input variables have types?
**Answer: Yes.**

```hcl
variable "app_port" {
  type = number
}
```

### Q109. Can variables have validation rules?
**Answer: Yes.**

```hcl
variable "environment" {
  type = string

  validation {
    condition     = contains(["dev", "prod"], var.environment)
    error_message = "Environment must be dev or prod."
  }
}
```

### Q110. What does `sensitive = true` do for a variable?
It tells Terraform to redact the value in appropriate CLI output and plans.

```hcl
variable "password" {
  type      = string
  sensitive = true
}
```

**Critical exam point:** Sensitive values may still be stored in Terraform state. `sensitive` is not encryption.

## 25. State and Sensitive Information

### Q111. Are input variable declarations themselves stored in state?
**Answer:** The declaration's metadata such as its description is not simply stored as a copy of the variable declaration. However, values used by resources and outputs can appear in state depending on how they are used.

### Q112. Are output values stored in state?
**Answer: Yes, output values are stored in state.

### Q113. Does marking a value sensitive prevent it from being stored in state?
**Answer: No.**

Sensitive values can still exist in state. Protect the state backend and access to state.

## 27. Dependency Lock File

### Q115. What is `.terraform.lock.hcl`?
**Answer:** Terraform's dependency lock file records selected provider versions and checksums so provider installation is reproducible.

### Q116. Does the lock file stop Terraform from ever selecting another provider version?
**Answer:** It influences provider selection, but it can be updated when configuration constraints change or when `terraform init -upgrade` is used and a newer allowed version is selected.

### Q117. Should `.terraform.lock.hcl` normally be committed to version control?
**Answer:** Yes, for root modules/configurations, committing it is generally recommended so teams and automation use consistent provider selections and checksums.

## 28. Implicit and Explicit Dependencies

### Q118. What is an implicit dependency?
A dependency Terraform can infer from an expression reference.

```hcl
resource "aws_eip" "lb" {
  instance = aws_instance.myec2.id
}
```

Terraform knows the EIP depends on the instance because the instance ID is referenced.

### Q119. What is an explicit dependency?
A dependency declared using `depends_on` when Terraform cannot infer the required ordering.

```hcl
resource "aws_instance" "example" {
  depends_on = [aws_iam_role_policy.example]
}
```

### Q120. Which is preferred when a dependency can be expressed through a reference?
**Answer:** Prefer an implicit dependency because it gives Terraform more precise dependency information. Use `depends_on` only when necessary.

## 29. Data Sources

### Q121. What is a data source?
**Answer:** A data source allows Terraform to read information that is defined or managed outside the current Terraform configuration.

Example:
```hcl
data "local_file" "foo" {
  filename = "${path.module}/demo.txt"
}
```

### Q122. Does a data source normally create the remote object?
**Answer: No.**

It reads existing information rather than managing creation of the object like a resource does.

## 30. HCP Terraform / Terraform Enterprise

### Q123. What is HCP Terraform?
**Answer:** HashiCorp's hosted Terraform platform, providing remote execution, state management, collaboration, policy/governance capabilities, and related features depending on plan.

### Q124. What is Terraform Enterprise?
**Answer:** HashiCorp's self-hosted/private Terraform platform for organizations requiring greater control over deployment environment and enterprise capabilities.

### Q125. What is a key difference between HCP Terraform and Terraform Enterprise?
**Answer:** HCP Terraform is hosted by HashiCorp, while Terraform Enterprise is designed to be deployed and operated in an organization's own environment.

### Q126. What does remote state storage provide?
**Answer:** It stores Terraform state in a shared remote location instead of only on an individual's local disk.

### Q127. What is a private module registry?
**Answer:** A registry for sharing and controlling access to reusable modules within an organization.

### Q128. What happens when a VCS-connected HCP Terraform workspace detects a relevant repository change?
**Answer:** Depending on the workspace's VCS/run settings, changes can trigger Terraform runs automatically.

### Q129. What does marking a variable as sensitive do in HCP Terraform?
**Answer:** It helps prevent the value from being displayed normally in the UI/log output.

**Exam distinction:** Sensitive handling reduces exposure; it does not make the value magically nonexistent or remove the need to secure state.

## 31. Replacing Resources

### Q130. How do you force replacement of a resource with modern Terraform?
Use `-replace` with `terraform apply`:

```bash
terraform apply -replace="aws_instance.web"
```

### Q131. What older command was used for this purpose?
**Answer:** `terraform taint`.

It is deprecated/replaced by the modern `-replace` workflow.

## 35. Splat Expressions

### Q138. What is a splat expression?
**Answer:** A concise way to obtain an attribute from all elements of a collection of objects.

Example:
```hcl
aws_instance.web[*].id
```

### Q139. Can splat expressions be used directly with resources created using `for_each`?
**Answer: No, not in the same way as with list-like `count` instances, because `for_each` instances are represented as a map.

For `for_each`, use a `for` expression when you need to collect values:

```hcl
[for instance in aws_instance.web : instance.id]
```

### Q140. What is the correct modern splat syntax?
```hcl
aws_instance.web[*].id
```

### Q141. What was the legacy splat syntax?
Older Terraform syntax used forms such as:

```hcl
aws_instance.web.*.id
```

Modern code should generally use the full splat syntax with `[*]`.

### Q142. Is this expression valid?

```hcl
aws_iam_user.lb.[*].name
```

**Answer: No.**

The extra dot before `[*]` is incorrect.

Correct:
```hcl
aws_iam_user.lb[*].name
```

## 36. Indexing Lists

### Q143. How do you retrieve the second element of a list?
Terraform uses zero-based indexing.

```hcl
var.size[1]
```

Example:
```hcl
variable "size" {
  type    = list(string)
  default = ["m5.large", "m5.xlarge", "t2.medium"]
}
```

`var.size[1]` returns `"m5.xlarge"`.

## 37. Large Infrastructure

### Q144. Why can large Terraform configurations become slow?
Cloud providers and APIs have rate limits and Terraform may need to manage many dependencies/resources.

### Q145. What is a better approach for very large environments?
Split infrastructure into sensible, independently managed configurations/modules/stacks with clear ownership and state boundaries.

### Q146. What is `-refresh=false`?
It prevents Terraform from refreshing remote object information during a command where that option is supported.

**Exam warning:** This can produce stale information and should not be used casually.

### Q147. Is `-target` recommended as a normal operating strategy?
**Answer: No.**

`-target` can be useful for exceptional recovery or troubleshooting scenarios, but normal Terraform operations should generally allow Terraform to evaluate the complete dependency graph.

## 38. Backends

### Q148. What is a Terraform backend?
**Answer:** A backend determines where Terraform stores state and, depending on the backend, how state operations such as locking are handled.

### Q149. What is the default backend?
**Answer:** The `local` backend.

### Q150. Where does the local backend store state?
By default, state is stored locally as `terraform.tfstate`.

### Q151. Can Terraform use an S3 backend?
**Answer: Yes, subject to the current backend configuration and provider/platform requirements.

Example:
```hcl
terraform {
  backend "s3" {
    bucket = "mybucket"
    key    = "path/to/my/key"
    region = "eu-west-2"
  }
}
```

### Q152. What happens when changing from a local backend to a remote backend?
Terraform can offer to migrate the existing state to the new backend.

### Q153. Can a backend be configured using variables?
**Answer:** Backend configuration is handled specially during initialization; normal Terraform input variable interpolation is not available in a backend block in the same way as ordinary configuration.

## 39. State Locking

### Q154. Why is state locking important?
**Answer:** It prevents conflicting operations from modifying shared state concurrently when the backend supports locking.

### Q155. Do all Terraform backends support locking?
**Answer: No.**

Locking capabilities depend on the backend.

### Q156. What happens if state is locked?
Operations that need to write state generally cannot proceed until the lock is released.

### Q157. What is `terraform force-unlock`?
It manually removes a state lock when Terraform cannot release it normally.

```bash
terraform force-unlock LOCK_ID
```

**Exam warning:** Use it carefully. Never force-unlock a state that another active Terraform process is legitimately using.

## 40. State and Version Control

### Q158. Should `terraform.tfstate` normally be committed to Git?
**Answer: No.**

State can contain sensitive information and should normally be stored in a properly secured backend.

### Q159. Should `.terraform/` normally be committed?
**Answer: No.**

It contains local working-directory/provider/module data that should generally not be committed.

### Q160. Should `.terraform.lock.hcl` normally be committed?
**Answer: Yes.**

It is intended to provide reproducible provider dependency selections/checksums.

### Q161. Should `*.tfvars` always be committed?
**Answer: No.**

Some `.tfvars` files contain secrets or environment-specific sensitive values. Treat them according to their contents and your team's secret-management policy.

## 41. Dynamic Blocks

### Q162. What is a dynamic block?
**Answer:** A dynamic block generates repeated nested blocks from a collection.

Example:
```hcl
dynamic "ingress" {
  for_each = var.sg_ports

  content {
    from_port   = ingress.value
    to_port     = ingress.value
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
}
```

### Q163. Where can dynamic blocks be used?
They can generate repeatable nested blocks where the containing construct supports nested blocks.

### Q164. What is a disadvantage of dynamic blocks?
**Answer:** Excessive use can make configurations harder to read, understand, and maintain.

**Exam point:** Do not use dynamic blocks when simple static blocks would be clearer.

## 44. Air-Gapped Environments

### Q168. What is an air-gapped environment?
**Answer:** A network/environment intentionally isolated from unsecured networks, commonly including the public Internet.

### Q169. Does Terraform always need direct Internet access to install providers?
**Answer: No.**

Air-gapped/offline environments can use provider mirrors or other supported installation mechanisms.

## 45. Terraform Version vs Provider Version

### Q171. Must Terraform and a provider have the same major version number?
**Answer: No.**

Terraform core and providers are versioned independently.

Compatibility is governed by the provider's requirements and the provider/Terraform compatibility supported by the versions being used.

## 46. Terraform Parallelism

### Q172. What does Terraform parallelism control?
**Answer:** It controls the maximum number of concurrent operations Terraform attempts, subject to dependency ordering and provider behavior.

### Q173. What is Terraform's default parallelism?

## 48. High-Value Exam Questions You Should Know

### Q188. What is the difference between a resource and a data source?
**Answer:**
- **Resource:** Terraform manages the lifecycle of the object.
- **Data source:** Terraform reads information about an existing/external object.

### Q189. What is the difference between `terraform.tfstate` and `.terraform.lock.hcl`?
**Answer:**
- `terraform.tfstate` = infrastructure/resource state.
- `.terraform.lock.hcl` = provider dependency selections/checksums.

### Q190. What is the difference between `count` and `for_each`?
**Answer:**
- `count` → numeric indexes.
- `for_each` → keys/set elements.
- `for_each` is often better where each instance has a meaningful stable identity.

### Q191. What is the difference between implicit and explicit dependency?
**Answer:**
- Implicit = inferred from references.
- Explicit = declared with `depends_on`.

### Q192. What is the difference between a variable and a local?
**Answer:**
- **Variable:** Input/parameter supplied to the module.
- **Local:** Named expression/value calculated inside the module.

### Q193. What is the difference between a module and a provider?
**Answer:**
- **Module:** Reusable Terraform configuration.
- **Provider:** Plugin that implements communication with an external API/platform.

### Q194. What is the difference between `terraform plan` and `terraform apply`?
**Answer:**
- `plan` previews proposed changes.
- `apply` performs the changes.

### Q195. What is the difference between `terraform state rm` and `terraform destroy`?
**Answer:**
- `state rm` forgets the resource in Terraform state but leaves the real object.
- `destroy` removes managed infrastructure.

### Q196. What is the difference between `terraform fmt` and `terraform validate`?
**Answer:**
- `fmt` = formatting.
- `validate` = configuration syntax/internal consistency.
